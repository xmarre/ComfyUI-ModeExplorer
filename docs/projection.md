# Projection-level numerical isolation

Set `projection_study=observe` on **ModeExplorer Mechanistic (Krea 2)** to measure the attention output projection at the existing `feature_block`. Use an empty `sites` string for projection-only measurements. The default `projection_study=off` keeps the existing research path. Ordinary ModeExplorer sampling keeps its existing settings.

On Krea 2 the native attention block calls its output linear on the elementwise product of the attention result and sigmoid gate. The new pre-hook captures that exact operand. The post-hook captures the result of the same call. Both snapshots include the entire packed sequence, with one positive row per matched auxiliary forward. The trace records dtype, device, shape, stride, storage offset and alignment modulo 16, followed by the generated-token slice for each arm. A geometry that cannot be reproduced with an independent snapshot is unqualified. Native replay uses the whole snapshot and compares both the full packed result and the generated-image error. No projection replay uses a shortened token sequence.

## Operator and weight qualification

The node observes the operand passed to one direct `torch.nn.functional.linear` call during each replay. It compares the actual effective weight and bias across the replays before interpreting an affine reference. Stable floating weights include merged LoRA or DoRA weights and the final dense operands produced by deterministic native runtime patch functions. Live-to-replay agreement is checked separately. No effective weight is cached across sampler states. Pre-quantization smoothing, other input transformations at the observed linear boundary, unrecognized quantized layouts, training and external projection hooks leave the reference unqualified.

For Kitchen's non-transposed `TensorWiseINT8Layout`, the reference uses the observed stored INT8 codes, scalar or output-channel scales, the observed bias and optional regular grouped Hadamard rotation in FP64. This estimates the ideal affine map implied by those stored operands. It does not load any unquantized training checkpoint or use an FP16 dequantized copy. The native path can pass a floating activation into Kitchen even when the outer ComfyUI quantization table marks `quantize_input=False`. In the audited Kitchen INT8 path the linear implementation can rotate and dynamically scale/round one flattened row per token, then do INT8 matrix multiplication, rescale and cast the output. Backend selection can branch on geometry and implementation. The trace gives the observed operand contract, installed Kitchen version and a registry dispatch candidate where available. The affine residual measures execution beyond the ideal map. The optional qualified quantizer replay below provides finer attribution.

Each native replay is compared with its captured original. Packed errors bound each response component using the triangle inequality. By default the upper error bound must be at most 5% of the observed positive, odd, even, half-amplitude and factorial responses that are present. A zero measured component requires a zero replay error bound. `native_replay` records packed equality and RMS, relative error and spatial and spectral diagnostics when an image discrepancy is observed. `effective_operator` is available after the native replay and weight checks qualify. A small reference error is measured by splitting the FP64 dot product and comparing the result, with an added FP32 reporting allowance. `residual_resolved` requires the residual L2 to exceed four times the larger of the reference floor and the replay bound.

## Reading the components

For each signed or conditioning component the forward path forms the input difference directly in FP64, then applies the effective weight with bias canceled. It also measures the corresponding native output difference and subtracts the affine prediction in FP64. The component maps are measured with the existing physically aligned bands in cycles per latent pixel. The `accounting` comparison uses the linear component as baseline and adds the residual. Its bandwise baseline, displacement and cross-term sum to the executed band energy, within reporting precision. This accounts for reinforcement and cancellation between the two fields. The input, linear, executed and residual entries include absolute energies, concentration, amplification and relative magnitude.

`projection_cast_check` adds a controlled single output cast of the FP64 affine prediction with bias to the native output dtype. It estimates how much even response that cast alone can produce. Native epilogue ordering or fused bias can differ. `projection_symmetric_check` makes two extra local native calls at the full baseline geometry. It creates exactly opposing representable image-token differences from the measured odd direction and leaves any axes that cannot realize the pair at baseline. Its trace reports the realized-to-requested L2 ratio and number of participating values. An even response there is execution-dependent for those inputs. It does not by itself identify the numerical operation responsible. The existing half-amplitude mechanism adds two full auxiliary arms and reports separate input, linear, executed and residual half/full magnitudes.

## Qualifying the activation counterfactual

`projection_activation_check` uses the observed effective INT8 weights and replays activation quantization over each original packed input. It selects the adapter for Kitchen's registry dispatch candidate.

- **Eager** uses the native-dtype rotation and eager per-token quantizer. It rescales the integer accumulation in FP32, casts the output, then adds bias in the output dtype. Every packed output must reproduce the captured native output bitwise.
- **CUDA** supports Kitchen 0.2.40 and 0.2.41's multirow INT8 GEMM path. It calls the fused ConvRot64 quantizer when the group, width and shared-memory predicate match. Other ConvRot groups use Kitchen's split rotation and CUDA rowwise quantization. The study tests the bias-before-cast and cast-then-bias models on the same replayed codes and exact integer products. The fused-bias candidates include sequential FP32 scaling with a separate bias add and with a fused final multiply-add. All arms in a state must qualify with the same epilogue. The check prefers a full packed bitwise match. Otherwise the sum of packed arm errors, weighted by the absolute component coefficients, must be at most `projection_replay_fraction` (default 0.05) of each measured component's L2. A zero component permits zero error.

`packed_routes` identifies the quantizer called by the diagnostic and the GEMM route eligible from Kitchen dispatch. CUTLASS can still decline a launch and fall through to cuBLAS. `qualification` records `bit_exact` or `component_bounded` for the selected epilogue. These checks qualify the replayed numerical model on the measured inputs. The trace makes no claim of direct observation of native kernel internals. Unsupported versions or a failed gate leave `activation_counterfactual.status=unqualified`; the packed native replay and FP64 affine analysis have their own gate.

A qualified report computes the signed or factorial response at four stages.

1. `native` uses the captured native output.
2. `no_activation_quantization` keeps the route's rotation precision and the replayed per-row FP32 scales. For fused ConvRot64 it uses Kitchen's standalone FP32 butterfly with the same arithmetic. It replaces integer activation coding with continuous row-normalized values and an FP64 product against the same stored INT8 weights. This removes activation division rounding, integer rounding and clipping as a group.
3. `no_rotation_rounding` uses an FP64 rotation along with continuous activations. The replayed row scales and selected epilogue are still used.
4. `ideal_affine` uses the direct FP64 affine reference.

The differences measure activation coding, rotation rounding and the selected epilogue in that order. The first difference inherits the epilogue model's packed replay error bound. `activation_quantization_resolved` requires its L2 to exceed four times `model_l2_bound`. Stage fields telescope in this sequence. Their squared L2 norms can overlap because the differences can reinforce or cancel. The transition metrics report the baseline field, displacement, cross-term and net band changes. The independent `projection_cast_check` still tests a single cast of an ideal affine result.

`quantization_transitions` counts changed INT8 codes and changed row scales for both signs relative to baseline, including changes unique to one sign and code changes on rows with unchanged scales. Counts are measured from the replayed quantizer's generated-image rows. The optional representable symmetric probe checks its packed outputs against the same epilogue using the baseline when bounding the even response. It reports stagewise even responses with an exact zero affine even component. If that probe fails its own gate, stage attribution for the other qualified arms remains available.

Four-arm conditioning mode uses the same fixed realized feature intervention under both prompts. It applies the affine reference to the actual projection-input factorial difference. The two contexts can have different text lengths, and all linear-component differences are taken after isolating each arm's generated tokens from the fully qualified native replay.

## Downstream isolation

After obtaining a qualified observation, choose `projection_study=executed`, `linear`, `residual` or `control`, set `component=complete`, and select the effect to isolate. The node runs one additional native baseline forward. It verifies the packed baseline input and output bitwise before adding the selected displacement only to the generated-image output tokens of the projection. The requested and native-rounded projection displacement norms are recorded. A residual or its deterministic control requires a resolved residual. The control matches its pre-cast L2. Signed and fixed-conditioning displacement tests also require the applicable realized intervention match. With `treatment=export_only` the sampler is observational and can export `projection_component_clean`. The existing `minimum_change` or external scorer treatment explicitly enables a bounded clean prediction candidate using the same CFG, trust and forecast routing rules as other active components. Keep `band=all` and the unfiltered location for an exact-component comparison. No downstream component preset is selected until the measured residual qualifies on the target checkpoint.

## Minimal planner campaign

All projection profiles use CUDA on the inference device. `capture_vram_mib` covers retained packed activations, a single effective weight snapshot, replay output, spectral scratch and token-chunked FP64 products. The trace reports `capture_preflight_bytes`, `capture_reserve_bytes`, `retained_packed_bytes`, `owned_effective_weight_bytes`, and separate `projection_native_replay`, `projection_reference` and `projection_spectral` timings. These are allocations owned or budgeted by the diagnostic. The native model and backend library workspaces also consume VRAM. CPU analysis with GPU inference skips packed projection studies because it cannot reproduce their device contract. CUDA allocation failure retains the native sampling result.

| Profile | What it tests | Auxiliary DiT calls | Local projection calls | Diagnostic preflight at 1632×2464 |
| --- | --- | --- | --- | --- |
| [Projection smoke](../examples/projection_smoke.json) | Can the exact executed operator and effective operand be qualified at the first actual state? | 4 | 3 | 14,056 MiB with a 16 GiB cap |
| [Projection signed](../examples/projection_signed.json) | Do even and odd responses follow the affine map, and do the excess responses persist at half amplitude or with exact input symmetry? | 18 across three states | Up to 7 per state | 22,242 MiB with a 24 GiB cap |
| [Projection conditioning](../examples/projection_conditioning.json) | Does the projection introduce an execution-dependent factorial interaction? | 5 at the first actual state | 4 | 16,012 MiB with a 16 GiB cap |

The table uses 6,144 channels, 512 packed non-image tokens, 32 spectral channels and 128 tokens per FP64 batch. The actual preflight uses the connected text and reference geometry, so longer packs can need more workspace. On this grid one full-width FP64 matrix product is about 1.19 TFLOP. The qualified smoke and conditioning profiles each use about 12 such product equivalents. The signed profile uses up to about 36 per state: 24 for the affine components, activation counterfactuals and symmetric probe, plus 12 for the output-cast check. Across three states that is roughly nine times the smoke profile's FP64 matrix work. Disabling `projection_cast_check` removes the 12 cast products per state. Those counts exclude rotation, spectral analysis, local native calls, and DiT work. Use the smoke run's `projection_reference` and `projection_activation_reference` timings for a wall-time estimate. `projection_activation_emulation` separately times packed qualification. An unqualified main replay skips the corresponding counterfactual products.

The workflows preserve a fixed seed and use Scale-Locked's verified planner-only path with ER-SDE and native evaluations. They save the planner latent to trigger the graph and require no VAE. Select the model and text encoder for your setup, and supply the established positive and alternate conditioning pair for the factorial test. The manifest holds replay evidence, spectral/spatial comparisons and the selected projection's operator contract. Safetensors exports retain the existing bounded native state and clean/candidate fields. Packed activations and weight copies never enter the export. The offline analyzer includes the projection report.

Run smoke first and inspect `mechanistic.projection.status`, `native_replay`, `effective_operator` and `activation_counterfactual.status`. For an activation-attribution study, proceed to the three-state signed profile after both qualifications pass and the smoke timings fit the experiment budget. The conditioning projection profile answers a separate localization question using the existing prompt pair. These measurements test numerical attribution and downstream sensitivity. Image quality requires an independently evaluated render.
